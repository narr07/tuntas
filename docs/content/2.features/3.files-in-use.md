---
title: Files in use
description: What happens when another program keeps a leftover file open.
navigation:
  icon: i-lucide-file-lock
---

Windows does not let anyone delete a file while a program has it open. That is a safety rule of Windows itself, and Tuntas respects it.

When a leftover cannot be deleted, Tuntas asks the Windows **Restart Manager** which programs or services hold its files. A dialog then shows them by name and offers four choices:

| Choice | What it does |
| --- | --- |
| **Close apps and retry** | Asks each program to close normally, as if you clicked its X, waits a few seconds, then tries again. Programs can still ask you to save your work. |
| **Force close** | Ends the programs immediately and tries again. Unsaved work in them is lost. |
| **Delete on restart** | Tells Windows to delete the files during the next boot, before any program can open them. Needs administrator rights. |
| **Skip** | Leaves the files where they are. |

Some special cases:

- **Services** are stopped with the Service Control Manager instead of being closed.
- **Windows Explorer** often holds files of programs that add items to the right-click menu. Closing it restarts the taskbar and desktop; open folder windows close.
- **Windows system processes** such as `csrss.exe`, `lsass.exe` or `svchost.exe` are never closed.

::note
Tuntas never forces open file handles closed inside another program. Some tools offer that, but the program keeps writing to a file it believes is still open, which can corrupt data or crash it.
::
