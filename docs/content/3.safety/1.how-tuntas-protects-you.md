An uninstaller that deletes the wrong folder can break Windows or wipe someone's documents. Tuntas has several independent layers so that one mistake is not enough.

## 1. Strict matching

Leftovers only match when their name is the program name, never when the words merely overlap. Folders shared by many programs are never matched. See [Leftovers](/features/leftovers).

## 2. Conservative defaults

Only items that clearly belong to the program are ticked. Every deletion ends in a dialog that lists exactly what will be removed.

## 3. The deletion guard

Before any file or folder is removed, its path is normalised (so `C:\Windows\..\Users` is seen as `C:\Users`) and checked against a list of protected places. Tuntas refuses to delete:

- any drive root, on every drive,
- the Windows folder and everything inside it,
- `Program Files`, `Program Files (x86)`, `ProgramData` and `Common Files` themselves,
- `C:\Users`, every user profile, and the known folders inside your profile (Desktop, Documents, Downloads, AppData and so on),
- shared folders such as `AppData\Microsoft`, `AppData\Local\Programs` and `AppData\Local\Packages`,
- system data such as Windows credentials, certificates and the Windows part of the Start Menu,
- any **parent** of the above, because deleting a parent would delete them too,
- Tuntas's own folder.

Network paths are refused as well.

## 4. Registry guard

Only keys under `SOFTWARE` can be removed, and only below the vendor level. `HKLM\SOFTWARE\Discord` can go; `HKLM\SOFTWARE`, `HKLM\SOFTWARE\Microsoft`, `HKCU\SOFTWARE\Classes` and keys that belong to Windows itself cannot.

## 5. Undo

Every deletion can be reversed. See [Undoing changes](/safety/undo).
